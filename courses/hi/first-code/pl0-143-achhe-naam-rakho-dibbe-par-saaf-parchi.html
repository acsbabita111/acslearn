पाठ परिचय

रसोई के दो घर सोचिए। पहले घर में डिब्बों पर पर्चियाँ हैं — "चीनी", "नमक", "हल्दी"। दूसरे में डिब्बों पर लिखा है — "डिब्बा-1", "डिब्बा-2", "ड"। मेहमान आए और चाय बनानी पड़े — पहले घर में दो मिनट; दूसरे में हर डिब्बा खोलकर सूँघो, चखो (और एक बार नमक वाली चाय!)। माल दोनों घरों में वही — पर पर्ची ने तय किया कि काम आसान होगा या आफ़त।

अब तक डिब्बों के नाम मैंने दिए — naam, umar, bhav, kul — और कभी-कभी सिर्फ़ a, b। आज यह ज़िम्मेदारी आपकी: अच्छे नाम रखो। इसके दो हिस्से हैं। पहला — Python के पक्के नियम: कुछ नाम Python बिल्कुल नहीं मानता (चिट्ठी देता है); कुछ मान तो लेता है पर उनसे हुक्म टूट जाते हैं (बिना चिट्ठी के, बाद में!)। दूसरा — नामकरण की तमीज़: Python a को भी मानता है और bhav_aalu को भी — पर छह महीने बाद आपका code पढ़ने वाला (आप ख़ुद!) किसे धन्यवाद देगा?

यह तमीज़ आपके लिए नई नहीं — पाठ-106 में CSS की class का "नाम मतलब से, रूप से नहीं" वाला हीरा, और पाठ-77 की "क्यों बताओ" वाली टिप्पणी। आज वही सोच, Python के डिब्बों पर। चलिए — पर्चियाँ लिखते हैं।

सीखने का उद्देश्य

इस पाठ के बाद आप —

1. Python के पाँच पक्के नाम-नियम बोल पाएँगे — और हर टूटे नियम की चिट्ठी पहचान पाएँगे।

2. हुक्म-नाम वाला डिब्बा (print = 5) क्यों ख़तरनाक है, समझा पाएँगे — चिट्ठी बाद में, कहीं और आती है।

3. नाम-तमीज़ निभा पाएँगे — मतलब से, छोटे अक्षर + अंडरस्कोर, न बहुत छोटा न बहुत लंबा, Roman में।

पक्के नियम — और नाम की तमीज़

पाँच पक्के नियम (कॉपी में — हर एक के आगे उसकी चिट्ठी): (1) अक्षर, अंक और अंडरस्कोर (_) ही — bhav_aalu ठीक; space वाला नाम — mera naam = ... — चिट्ठी: SyntaxError: invalid syntax; डैश वाला — mera-naam = ... — चिट्ठी: "cannot assign to expression" (Python को डैश घटाव-चिह्न लगता है: "mera माइनस naam"!)। इसलिए शब्द जोड़ने को अंडरस्कोर (_ — नीचे की लकीर; कीबोर्ड पर अक्सर "?123" के पीछे) — CSS की class में हाइफ़न था (पाठ-106), Python में अंडरस्कोर। (2) अंक से शुरू नहीं — 2naam = ... → SyntaxError: invalid decimal literal; naam2 ठीक। (3) बड़े-छोटे अलग — Naam और naam दो अलग डिब्बे (पाठ-136 की सख़्ती!)। (4) Python के अपने शब्द नहीं — if, for, while, True, False, None, and, or, not जैसे कुछ गिने-चुने शब्द Python के "आरक्षित" हैं (keyword — कीवर्ड); if = 5 → SyntaxError। (5) हुक्मों के नाम पर डिब्बा मत बनाओ — यह नियम Python ख़ुद नहीं रोकता, इसीलिए सबसे ख़तरनाक (नीचे)।

सबसे चुप ख़तरा — print = 5: print कोई आरक्षित शब्द नहीं — वह बस एक नाम है, जिसके डिब्बे में Python ने "छापने का हुक्म" रखा है। आप print = 5 लिखें, तो Python चुपचाप मान लेता है — और उस डिब्बे में हुक्म की जगह 5 रख देता है! अगली ही पंक्ति print("Sita") पर चिट्ठी: TypeError: 'int' object is not callable — "5 कोई हुक्म नहीं, उसे बुलाया नहीं जा सकता"। ख़तरा यह कि चिट्ठी उस पंक्ति पर नहीं आती जहाँ ग़लती हुई (print = 5), बल्कि बाद में, जहाँ print बरता गया — पाठ-110 के "ग़लती ऊपर, लक्षण नीचे" जैसा। इसलिए नियम: print, type, input, sum, list जैसे नामों पर कभी डिब्बा नहीं (अजीब लगे तो पहले देखिए: वह शब्द कहीं हुक्म तो नहीं?)।

अब तमीज़ — Python मान लेगा, पर पाठक? 🔮 अंदाज़ा लगाइए — नीचे के दोनों प्रोग्राम एक ही हिसाब करते हैं; कौन-सा पढ़कर तुरंत समझ आता है कि क्या हो रहा है? नतीजा दोनों का क्या होगा? —

a = 45
b = 3
print(a * b)
bhav_aalu = 45
kilo_aalu = 3
kul_aalu = bhav_aalu * kilo_aalu
print("Aalu ka kul:", kul_aalu)

नतीजा: दोनों 135 — Python के लिए कोई फ़र्क़ नहीं। पर पहले को पढ़कर कोई बताए "a क्या है? b?" — कोई नहीं जानता; दूसरा ख़ुद बोलता है। चार तमीज़ें (कॉपी में): (1) मतलब से — डिब्बे में क्या है (bhav_aalu), उसका रूप या जगह नहीं (dibba1)। (2) छोटे अक्षर + अंडरस्कोर — kul_rupaye, bhav_aalu (Python की दुनिया की आम रीत; बड़े-छोटे की उलझन भी घटती है)। (3) न बहुत छोटा, न बहुत लंबा — a बहुत छोटा (बेमतलब), aaj_subah_bazaar_me_khareede_gaye_aaluon_ka_bhav बहुत लंबा (टाइप में ग़लती, पढ़ने में थकान); bhav_aalu — बीच का। (अपवाद: बहुत छोटे, एक-दो पंक्ति के काम में a, b, x चल जाते हैं — जैसे पाठ-142 का प्रयोग।) (4) Roman में — Python देवनागरी नाम भी मान लेता है (नाम = "सीता" चलता है!), पर ACS-रीत: नाम सदा Roman — हुक्मों की तरह (पाठ-65 का लिपि-नियम); कीबोर्ड पर आसान, दुनिया में कहीं भी पढ़ा जाए। माल (उल्टे-कॉमा के भीतर) अपनी लिपि में, जैसे पहले।

रेखा-चित्र: डिब्बे की पर्ची

नीचे आज का पूरा पट्ट — पाँच नियम और उनकी चिट्ठियाँ, print-डिब्बे का चुप ख़तरा, और नाम की चार तमीज़ें —

बीच की सुनहरी पट्टी आज का सबसे ज़रूरी डिब्बा है — Python हर ग़लत नाम पर चिट्ठी नहीं देता; जो नाम वह चुपचाप मान ले पर हुक्म तोड़ दे, उसकी चिट्ठी बाद में, कहीं और आती है।

ग़लतफ़हमी तोड़ो

ग़लतफ़हमी: "नाम तो मेरी मर्ज़ी — छोटे रखूँगा, जल्दी टाइप होंगे! a, b, c, x, y — सब समझ में आता है, मैंने ही तो लिखा है। लंबे नाम सिर्फ़ समय बर्बाद करते हैं। और मशीन को नाम से क्या फ़र्क़ पड़ता है?"

सच: "मशीन को फ़र्क़ नहीं पड़ता" — बिल्कुल सही! Python के लिए a और bhav_aalu बराबर हैं। पर code सिर्फ़ मशीन के लिए नहीं लिखा जाता — वह इंसानों के लिए भी है: कल के आप, आपका दोस्त जो जोड़ी-जाँच करेगा (पाठ-126), कोई उस्ताद जिससे मदद माँगेंगे। दुनिया भर के प्रोग्रामरों में एक पुरानी कहावत है: code एक बार लिखा जाता है, पर दस बार पढ़ा जाता है। a लिखने में एक सेकंड बचा; उसे पढ़कर समझने में हर बार दस सेकंड गए — दस बार पढ़ा, तो सौ सेकंड। लंबा नाम असल में समय बचाता है, सिर्फ़ पहली बार नहीं, हर बार।

और "मैंने ही तो लिखा, मुझे समझ आता है" — आज समझ आता है। एक हफ़्ते बाद अपना पुराना code खोलिए जिसमें a, b, c, x हैं — और देखिए कितनी देर लगती है याद करने में कि c क्या था। (पाठ-77 की टिप्पणी वाली बात याद है — "भविष्य के आप सबसे भुलक्कड़ पाठक हैं"!) बड़े प्रोग्राम में यह आफ़त बन जाती है: चालीस डिब्बे, सब अक्षर-नाम — किसी में भाव, किसी में किलो, किसी में कुल — और एक गुणा ग़लत डिब्बे से, तो पूरा बिल ग़लत, और ढूँढना लगभग असंभव। मतलब-नाम वाले डिब्बों में ग़लती दिखती है: kul = bhav_aalu * bhav_pyaaz — "भाव गुणा भाव? यह ग़लत है!" — नाम ने ख़ुद पकड़ा दी। अच्छा नाम मशीन के लिए नहीं — पढ़ने वाले के लिए दवा है, और ग़लती के लिए जासूस।

अभ्यास-खेल: पर्ची-मश्क़

खेल 1 — नाम-अदालत (दस नाम): कॉपी में हर नाम पर फ़ैसला — ✗ Python नहीं मानेगा (कौन-सा नियम?) / ⚠ मानेगा पर ख़तरनाक / ✓ ठीक, पर तमीज़? / ✓✓ बढ़िया: (क) kul rupaye (ख) 3kilo (ग) bhav_aalu (घ) print (ङ) if (च) x (छ) Kul (ज) doodh-litre (झ) doodh_litre (ञ) type। फिर (मशीन हो तो) ✗ वालों को चलाकर उनकी चिट्ठी की आख़िरी पंक्ति कॉपी में — आपका फ़ैसला मिला?

खेल 2 — अक्षर-नामों का अनुवाद: यह प्रोग्राम कॉपी में लिखिए: a = 30 · b = 12 · c = a * b · d = c - 50 · print(d)। 🔮 पहले सूखी-दौड़ (डिब्बा-तालिका — पाठ-140!) — d क्या छपेगा? फिर सोचिए यह किस चीज़ का हिसाब हो सकता है (30 रुपये रोज़, 12 दिन, 50 पेशगी?) — और हर डिब्बे का मतलब-नाम रखकर दोबारा लिखिए। दोनों रूप किसी साथी को दिखाइए: "इनमें से कौन-सा बताता है कि क्या हो रहा है?"

खेल 3 — print-डिब्बे का चुप ख़तरा (नक़ल पर!) + हुक्म-बही: print = "Sita" · print(print) — 🔮 दाँव: क्या होगा? — चलाइए, चिट्ठी नीचे से ऊपर (कौन-सी पंक्ति? ग़लती किस पंक्ति में थी?)। सीख: "चिट्ठी जहाँ आई, ग़लती वहाँ नहीं थी" — बीमारी-पट्टी में नोट (कल के दवाख़ाने का एक मरीज़ यही है!)। हुक्म-बही के डिब्बा-पन्ने पर: पाँच नियम + चार तमीज़ें, और एक पंक्ति मोटी: "हुक्म-नाम पर डिब्बा कभी नहीं"।

आगे क्या सीखेंगे

डिब्बों पर साफ़ पर्चियाँ लग गईं — Python के पाँच पक्के नियम (अक्षर-अंक-अंडरस्कोर, अंक से शुरू नहीं, बड़े-छोटे अलग, आरक्षित शब्द नहीं, हुक्म-नाम पर डिब्बा नहीं), print = 5 का चुप ख़तरा, और चार तमीज़ें (मतलब से, छोटे + अंडरस्कोर, बीच की लंबाई, Roman)। आपका code अब पढ़ने वाले से बात करता है।

कल इस अध्याय की वह बात जिसे Python सीखने वाले दुनिया भर में सबसे ज़्यादा ग़लत समझते हैं — मशहूर ग़लतफ़हमी: डिब्बा इतिहास "याद" नहीं रखता। पाठ-139 और 140 में उसकी दो झलकें मिलीं (kul अपने-आप नहीं बदला; बदला हुआ माल हमेशा के लिए गया); कल पूरी पहेली: b = a लिखने के बाद a बदला — तो b? क्या दोनों डिब्बे "जुड़े" हैं? क्या b, a का पीछा करेगा? और दो डिब्बों का माल अदला-बदली करना हो (a में b का, b में a का) — सीधा रास्ता क्यों फ़ेल होता है, और ठेलेवाले की "तीसरी टोकरी" वाली चाल क्यों काम करती है। पाठ-144: मशहूर ग़लतफ़हमी — डिब्बा इतिहास "याद" नहीं रखता, सिर्फ़ ताज़ा चीज़।
