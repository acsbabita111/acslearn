पाठ परिचय

बड़े डाकघर में एक कमरा होता है जहाँ हज़ारों चिट्ठियों के रजिस्टर रखे होते हैं — हर पंक्ति में एक चिट्ठी: भेजने वाला, पाने वाला, तारीख़, वज़न। कोई पूछे "खगड़िया से पिछले हफ़्ते कितनी रजिस्ट्री गईं?" — बाबू जी रजिस्टर पलटते हैं, पंक्ति-दर-पंक्ति गिनते हैं — घंटा भर। अब सोचिए अगर रजिस्टर से सीधे सवाल पूछा जा सके — "खगड़िया वाली, पिछले हफ़्ते की, गिनो" — और जवाब पल में।

बैंक, राशन-दुकान, अस्पताल, परीक्षा-बोर्ड, बड़ी दुकानें — सबके पास ऐसे विशाल "रजिस्टर" होते हैं, कंप्यूटर में: उन्हें हिसाब-घर (database — डेटाबेस) कहते हैं। और उनसे सवाल पूछने की, आज दुनिया भर में सबसे ज़्यादा बरती जाने वाली साझा भाषा है SQL (एस-क्यू-एल; "Structured Query Language" — "ढाँचेदार सवाल की भाषा")। जब आप परीक्षा-परिणाम की वेबसाइट पर अपना नंबर डालते हैं, तो पीछे आम तौर पर ऐसा ही कोई सवाल चलता है: "इस नंबर वाले बच्चे के अंक दिखाओ"।

और आज इस अध्याय में पहली बार एक दूसरी भाषा आप असली चलाएँगे: Python के साथ एक छोटी बनी-बनाई पेटी आती है — sqlite3 — जिसके भीतर एक छोटा-सा हिसाब-घर बनाकर उससे SQL में सवाल पूछे जा सकते हैं। इसलिए आज के SQL-डिब्बे सचमुच चलते हैं, और इस किताब का robot उन्हें जाँचता है! चलिए — रजिस्टर से सवाल पूछते हैं।

सीखने का उद्देश्य

इस पाठ के बाद आप —

1. बता पाएँगे कि हिसाब-घर (database) क्या है — पाठ-93 की तालिका का बहुत बड़ा, सवाल-योग्य रूप — और SQL किसलिए।

2. चार SQL-हुक्म पढ़ पाएँगे — CREATE TABLE, INSERT, SELECT ... WHERE ... ORDER BY, और COUNT/SUM — Python की sqlite3 पेटी में चलाकर।

3. SQL के "सवाल" और Python के "लूप" का फ़र्क़ समझा पाएँगे — और एक सुरक्षा-नियम (बाहर का जवाब सीधे SQL में नहीं)।

रजिस्टर से सवाल

हिसाब-घर = बहुत बड़ी तालिका (कॉपी में): पाठ-93 याद है — HTML की तालिका: पंक्तियाँ (tr) और ख़ाने (td)? हिसाब-घर में भी तालिका (table) होती है — हर पंक्ति एक चीज़ (एक ग्राहक, एक चिट्ठी, एक सामान), हर स्तंभ एक जानकारी (नाम, भाव, तारीख़)। फ़र्क़: HTML-तालिका दिखाने के लिए, हिसाब-घर की तालिका सवाल पूछने के लिए — और उसमें लाखों पंक्तियाँ हो सकती हैं।

पहला हिसाब-घर — 🔮 अंदाज़ा पहले: नीचे Python, sqlite3 पेटी से एक छोटा हिसाब-घर बनाता है (":memory:" = "बस अभी के लिए, याद में" — प्रोग्राम ख़त्म, हिसाब-घर ख़त्म), उसमें चार सामान डालता है, और SQL में सवाल पूछता है: "30 या ज़्यादा भाव वाले, भाव के क्रम में"। दाँव: कौन-कौन से, किस क्रम में? —

import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE saman (naam TEXT, bhav INTEGER)")
db.execute("INSERT INTO saman VALUES ('aalu', 40)")
db.execute("INSERT INTO saman VALUES ('pyaaz', 30)")
db.execute("INSERT INTO saman VALUES ('tamatar', 50)")
db.execute("INSERT INTO saman VALUES ('namak', 20)")

for pankti in db.execute("SELECT naam, bhav FROM saman WHERE bhav >= 30 ORDER BY bhav"):
    print(pankti)

नतीजा: ('pyaaz', 30) ('aalu', 40) ('tamatar', 50) — नमक (20) छँट गया, बाक़ी भाव के क्रम में। (हर पंक्ति गोल कोष्ठक में एक जोड़ी — Python इसे tuple (टपल) कहता है — सूची जैसी, पर बदली न जा सकने वाली; आज बस पहचान।)

चार SQL-हुक्म पढ़ो (उल्टे-कॉमा के भीतर वाले हिस्से — कॉपी में): (1) CREATE TABLE saman (naam TEXT, bhav INTEGER) — "saman नाम की तालिका बनाओ — दो स्तंभ: naam (शब्द), bhav (पूरी गिनती)" — पाठ-142 की क़िस्में, यहाँ पहले से तय! (2) INSERT INTO saman VALUES ('aalu', 40) — "तालिका में एक पंक्ति डालो" (सूची का append, पाठ-177!)। (3) SELECT naam, bhav FROM saman WHERE bhav >= 30 ORDER BY bhav — पढ़िए लगभग अंग्रेज़ी वाक्य की तरह: "saman से naam और bhav चुनो, जहाँ bhav 30 या ज़्यादा, bhav के क्रम में" — WHERE = if की छँटाई (पाठ-168), ORDER BY = sort (पाठ-182)। SQL के हुक्म-शब्द बड़े अक्षरों में लिखने की आदत है (ज़रूरी नहीं, पर पढ़ने में साफ़)।

गिनती और जोड़ — एक सवाल में: 🔮 अंदाज़ा — चार चीज़ें, भाव 40, 30, 50, 20 —

import sqlite3

db = sqlite3.connect(":memory:")
db.execute("CREATE TABLE saman (naam TEXT, bhav INTEGER)")
db.execute("INSERT INTO saman VALUES ('aalu', 40)")
db.execute("INSERT INTO saman VALUES ('pyaaz', 30)")
db.execute("INSERT INTO saman VALUES ('tamatar', 50)")
db.execute("INSERT INTO saman VALUES ('namak', 20)")

ginti = db.execute("SELECT COUNT(*) FROM saman").fetchone()
kul = db.execute("SELECT SUM(bhav) FROM saman").fetchone()
print("Kitni cheezein:", ginti[0])
print("Sab bhav ka jod:", kul[0])

नतीजा: Kitni cheezein: 4 और Sab bhav ka jod: 140। COUNT = len (पाठ-179), SUM = sum (पाठ-178)। fetchone() = "जवाब की पहली पंक्ति लाओ", और उसके पता 0 पर जवाब (पाठ-176 के पते, फिर से!)।

SQL का सवाल बनाम Python का लूप: यही काम Python की सूची और लूप से भी होता था (पाठ 178-182) — फिर SQL क्यों? क्योंकि हिसाब-घर में लाखों पंक्तियाँ होती हैं, और वह हमेशा सहेजा रहता है (फ़ाइल में, सर्वर पर); SQL में आप बस बताते हैं क्या चाहिए ("30 से ज़्यादा वाले"), कैसे खोजना है — वह हिसाब-घर ख़ुद तय करता है, बहुत तेज़ ढंग से। Python में आप कैसे लिखते हैं (लूप, if); SQL में क्या। (दोनों साथ चलते हैं — जैसे आज: Python ने हिसाब-घर बनाया, SQL ने सवाल पूछा।)

एक सुरक्षा-नियम (आगे के लिए, कॉपी में मोटा): खिलाड़ी या ग्राहक से आए जवाब को सीधे SQL-सवाल के शब्दों में जोड़ना ख़तरनाक है — कोई चालाक व्यक्ति जवाब में ही SQL का हुक्म लिख दे, तो हिसाब-घर उसे चला सकता है (दुनिया में इस तरह के हमलों के मशहूर मामले हैं)। इलाज के सुरक्षित ढंग हैं (आगे के कोर्स में) — आज बस पाठ-164 का नियम बड़े रूप में: बाहर से आए हर जवाब पर शक करो। मुफ़्त घाट: sqlite का आधिकारिक घर sqlite.org (अंग्रेज़ी) (बाहरी site — जानकारी ख़ुद verify करें)।

जानकारी-जाँची: अक्टूबर 2026

रेखा-चित्र: रजिस्टर से सवाल

नीचे हिसाब-घर की तालिका, एक SQL-सवाल का सफ़र, और SQL-हुक्मों का Python से मिलान —

ऊपर की तीन पट्टियाँ एक सवाल का सफ़र हैं — बाएँ तालिका की चार पंक्तियाँ, बीच में सवाल, दाएँ नतीजा; धारीदार "namak" वह पंक्ति है जिसे WHERE ने छाँट दिया।

ग़लतफ़हमी तोड़ो

ग़लतफ़हमी: "database तो Excel की फ़ाइल जैसा ही है — एक बड़ी तालिका! Excel आता है, तो SQL की क्या ज़रूरत? और SQL सिर्फ़ बड़ी कंपनियों का काम है।"

सच: दोनों तालिकाएँ हैं — पर काम अलग (कल का Excel-पाठ यह और साफ़ करेगा)। Excel की फ़ाइल आम तौर पर एक इंसान के लिए है — वह ख़ुद देखता है, ख़ुद सुधारता है, कुछ हज़ार पंक्तियाँ। हिसाब-घर कई लोगों और कई प्रोग्रामों के लिए है — एक साथ हज़ारों लोग (बैंक की सब शाखाएँ, सब ATM, मोबाइल-ऐप) उससे सवाल पूछते हैं, उसमें लिखते हैं, और वह ध्यान रखता है कि दो लोग एक ही खाते से एक साथ पैसा निकालें तो गड़बड़ न हो। लाखों-करोड़ों पंक्तियाँ, हर पल बदलती, फिर भी सही। Excel से यह नहीं हो सकता — और SQL से Excel जैसी सजावट नहीं होती। दोनों अपने काम के औज़ार (पाठ-205: भाषा काम से चुनो)।

और "सिर्फ़ बड़ी कंपनियों का काम" — आज जिस sqlite3 पेटी से आपने हिसाब-घर बनाया, उस जैसे छोटे हिसाब-घर आपके फ़ोन के भीतर भी बहुत-से ऐपों में चलते हैं — संपर्क-सूची, संदेश, ऐप की सेटिंग जैसी चीज़ें अक्सर ऐसे ही छोटे हिसाब-घरों में सहेजी जाती हैं। गाँव की किसी दुकान का हिसाब, किसी कोचिंग-केंद्र की हाज़िरी और फ़ीस, किसी किसान-समूह की उपज का रजिस्टर — इन सबके लिए छोटा हिसाब-घर और थोड़ी-सी SQL काफ़ी है (पाठ-216 का "गाँव में पहला काम" — एक दिशा!)। और दफ़्तरों में "SQL आती है?" एक आम सवाल है, क्योंकि लगभग हर बड़ी जानकारी किसी हिसाब-घर में ही रहती है। हिसाब-घर बड़ी तालिका भर नहीं — कई लोगों का साझा, हमेशा-सही रजिस्टर है; और SQL उससे बात करने की दुनिया की साझा बोली।

अभ्यास-खेल: रजिस्टर-मश्क़

खेल 1 — अपना हिसाब-घर: आज के पहले डिब्बे को लेकर अपनी तालिका बनाइए — कक्षा के छह बच्चे (काल्पनिक नाम — पाठ-59!), स्तंभ naam और ank। फिर चार सवाल, हर एक पर पहले दाँव: (क) सब बच्चे, अंकों के क्रम में (ख) सिर्फ़ 33 या ज़्यादा वाले (ग) कितने बच्चे पास (COUNT के साथ WHERE!) (घ) सबसे ज़्यादा अंक (MAX(ank) — अनुमान लगाइए, आज़माइए!)।

खेल 2 — उलटा क्रम और दो शर्तें: (क) ORDER BY bhav DESC — DESC का मतलब क्या निकला? (उलटा — बड़े से छोटा; पाठ-182 का reverse!) (ख) WHERE bhav >= 30 AND bhav <= 45 — कौन बचा? (पाठ-162 का and — SQL में बड़े अक्षरों में!) (ग) एक सामान दोबारा INSERT कीजिए — COUNT कितना? (हिसाब-घर दोहराव नहीं रोकता, जब तक आप नियम न बनाएँ — पाठ-184 की "pehle se hai" जाँच याद है?)

खेल 3 — Python बनाम SQL + हुक्म-बही: खेल-1 का सवाल (ख) Python की सूची और लूप से भी कीजिए (पाठ-168 का ढंग)। दोनों के जवाब एक-से? कौन-सा code छोटा? कौन-सा लाख बच्चों पर बेहतर रहेगा, और क्यों? पाठ-205 की तालिका में SQL-पंक्ति भरिए। हुक्म-बही के भाग-द पन्ने पर: "हिसाब-घर = साझा, बड़ी तालिका · SQL = उससे सवाल · CREATE · INSERT · SELECT-FROM-WHERE-ORDER BY · COUNT, SUM · SQL में क्या, Python में कैसे · बाहर का जवाब सीधे SQL में नहीं"।

आगे क्या सीखेंगे

रजिस्टर से सवाल पूछ लिया — हिसाब-घर (बहुत बड़ी, साझा, सवाल-योग्य तालिका), SQL के चार हुक्म (CREATE, INSERT, SELECT-WHERE-ORDER BY, COUNT-SUM) — Python की sqlite3 पेटी में असली चलाकर, SQL का "क्या" बनाम Python का "कैसे", और बाहर के जवाब वाला सुरक्षा-नियम।

कल परिवार की वह सदस्य जो सबसे ज़्यादा दफ़्तरों में मिलती है — इतनी आम कि कई लोग उसे "भाषा" मानते ही नहीं: Excel के सूत्र (formulas)। वेतन-पत्रक, फ़ीस का हिसाब, दुकान का स्टॉक, स्कूल के अंक — कहीं भी जाइए, कोई तालिका-ऐप खुला मिलेगा, और उसके ख़ानों में =SUM(...), =IF(...) जैसे सूत्र। कल उनकी झलक — और यह खोज कि IF सूत्र आपके Python वाले if का ही भाई है; साथ में Python से "दो रास्ते" वाली जाँच, और मुफ़्त विकल्प जिन पर वही सूत्र चलते हैं। पाठ-210: एक्सेल (Excel)-सूत्र — दफ़्तर की रोज़ी।
