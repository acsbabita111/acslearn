पाठ परिचय

गाँव में दो तरह के मिस्त्री होते हैं। एक वह जो मोटरसाइकिल का बाहरी काम करता है — टायर, ब्रेक, बत्ती — औज़ार आसान, काम जल्दी। दूसरा वह जो इंजन खोलता है — पिस्टन, वाल्व, एक-एक पुर्ज़े का नाप। उसका काम धीमा, सावधानी वाला, ज़्यादा जानकारी माँगने वाला — पर मशीन के दिल तक उसी की पहुँच है।

कंप्यूटर-भाषाओं में Python पहले मिस्त्री जैसी है — आरामदेह, मशीन की बारीकियाँ आपसे छिपाकर रखती है। C (सी) दूसरे जैसी — वह आपको मशीन के अंदर ले जाती है। यह दुनिया की सबसे पुरानी और आज भी सबसे ज़्यादा बरती जाने वाली भाषाओं में से एक है (लगभग पचास साल से ज़्यादा पुरानी, फिर भी लोकप्रियता-सूचियों में ऊपर — पाठ-205)। आपके फ़ोन और कंप्यूटर का भीतरी तंत्र (operating system — ऑपरेटिंग सिस्टम) का बड़ा हिस्सा, वॉशिंग-मशीन और माइक्रोवेव के भीतर का छोटा "दिमाग़", इंटरनेट से जुड़ी छोटी स्मार्ट मशीनें (IoT — Internet of Things — "चीज़ों का इंटरनेट"), और ड्रोन के उड़ान-तंत्र — इनमें बहुत-सा code C या उसकी रिश्तेदार भाषाओं में होता है।

आज एक छोटा C-नमूना देखेंगे, Python के जुड़वाँ से मिलाएँगे, और तीन बड़ी बातें समझेंगे: C में हर डिब्बे की क़िस्म पहले बतानी पड़ती है; C का प्रोग्राम पहले पूरा अनुवाद (compile) होकर चलता है; और यह अनुवाद पाठ-3 वाली 0-1 मशीन-भाषा तक जाता है — परिवार की बारहवीं सदस्य। (C-नमूना धारीदार डिब्बे में — robot C नहीं चलाता।) चलिए — इंजन खोलते हैं।

सीखने का उद्देश्य

इस पाठ के बाद आप —

1. बता पाएँगे कि C कहाँ काम आती है — भीतरी तंत्र, छोटी मशीनें (IoT), ड्रोन — और क्यों उसे "मशीन के पास" कहते हैं।

2. एक छोटा C-नमूना पढ़ पाएँगे — #include, main, int, धनु-कोष्ठक, अर्धविराम, printf — और Python से मिला पाएँगे।

3. compile बनाम दुभाषिया का फ़र्क़ समझा पाएँगे — और C से 0-1 मशीन-भाषा तक का पुल।

इंजन खोलो

C का एक नमूना (धारीदार डिब्बा = नमूना): वही पुराना पास-फ़ेल का फ़ैसला (पाठ-158), C में —

#include <stdio.h>

int main(void) {
    int ank = 40;
    if (ank >= 33) {
        printf("Paas\n");
    } else {
        printf("Mehnat\n");
    }
    return 0;
}

Python-जुड़वाँ — 🔮 अंदाज़ा (यह robot चलाता है; आख़िरी पंक्ति में डिब्बे की क़िस्म भी — पाठ-142 का type) —

ank = 40
if ank >= 33:
    print("Paas")
else:
    print("Mehnat")
print(type(ank))

नतीजा: Paas और <class 'int'> — Python ने ख़ुद पहचाना कि ank एक पूरी गिनती (int) है।

C-नमूना पढ़ो (कॉपी में, पंक्ति-दर-पंक्ति): #include <stdio.h> — "छपाई वाली पेटी लाओ" (Python के import जैसा — पाठ-195!); int main(void) { ... } — हर C-प्रोग्राम का एक मुख्य पुर्ज़ा, जहाँ से काम शुरू होता है (पाठ-186 का दो-मंज़िला ढंग — यहाँ "निचली मंज़िल" का नाम ही main है); int ank = 40; — सबसे बड़ा फ़र्क़: डिब्बा बनाते समय उसकी क़िस्म पहले बतानी पड़ती है — int (पूरी गिनती)। Python ख़ुद पहचान लेता था (type दिखाता है); C में आप बताते हैं, और फिर उस डिब्बे में कोई शब्द रखने की कोशिश करो, तो C अनुवाद के समय ही रोक देती है। if (ank >= 33) { ... } — वही if, शर्त गोल कोष्ठक में, शरीर धनु-कोष्ठक में (कल परसों वाली JavaScript जैसा!); printf("Paas\n"); — छपाई (print जैसा); \n = "नई पंक्ति" (Python का print यह अपने-आप लगाता है — याद है end=""? पाठ-165); और हर पंक्ति के अंत में अर्धविराम। return 0; — "सब ठीक रहा" का संकेत (पाठ-188 का return, मुख्य पुर्ज़े से)।

compile बनाम दुभाषिया (कॉपी में मोटा): Python का प्रोग्राम चलाते समय एक दुभाषिया (interpreter) पंक्ति-दर-पंक्ति पढ़कर चलाता है — जैसे सभा में दुभाषिया वक्ता के हर वाक्य का तुरंत अनुवाद करे (इसीलिए पाठ-186 में बनाने से पहले बुलाने पर रुकावट उसी पंक्ति पर आई!)। C का प्रोग्राम पहले पूरा का पूरा अनुवाद होता है — एक "अनुवादक" (compiler — कंपाइलर) उसे मशीन की अपनी 0-1 वाली भाषा में बदलकर एक नई फ़ाइल बनाता है, और फिर वह फ़ाइल चलती है — जैसे पूरी किताब का अनुवाद छपकर तैयार हो, फिर पाठक पढ़े। फ़ायदा: अनुवाद हो चुका, तो चलना बहुत तेज़; और कई ग़लतियाँ (जैसे int डिब्बे में शब्द) अनुवाद के समय ही पकड़ में आ जाती हैं। क़ीमत: हर बदलाव के बाद फिर से अनुवाद, और लिखने में ज़्यादा सावधानी।

पाठ-3 तक का पुल — परिवार की बारहवीं सदस्य: अनुवादक जो फ़ाइल बनाता है, वह मशीन-भाषा है — 0 और 1 के लंबे-लंबे सिलसिले, जिन्हें कंप्यूटर का दिमाग़ (प्रोसेसर) सीधे समझता है (पाठ-3: "कंप्यूटर की अपनी बोली — सिर्फ़ 0 और 1")! इंसान के पढ़ने लायक़ उसका एक रूप भी होता है — "असेंबली" (assembly) — छोटे-छोटे हुक्म-शब्द, हर एक मशीन के एक काम के बराबर। ऊपर से नीचे: Python/JavaScript → C → असेंबली → 0-1 — जितना नीचे, उतना मशीन के पास, और उतना इंसान से दूर। आपकी हर भाषा अंत में इसी 0-1 तक उतरती है — पाठ-3 का बीज, आज पूरा पेड़।

दिशा — छोटी मशीनें (IoT, ड्रोन): छोटी मशीनें बनाने-सिखाने का एक मशहूर, खुला रास्ता Arduino नाम के छोटे बोर्ड हैं, जिन्हें C/C++ जैसी भाषा से चलाया जाता है (नाम सिर्फ़ उदाहरण — इसके लिए बोर्ड और कंप्यूटर चाहिए, यानी कुछ ख़र्च) (बाहरी site — जानकारी ख़ुद verify करें)। C सीखने के मुफ़्त रास्तों में SWAYAM/NPTEL पर C-प्रोग्रामिंग के कोर्स भी रहे हैं (पाठ-206 वाले नियम — पढ़ना मुफ़्त, प्रमाणपत्र-परीक्षा शुल्क वाली)।

रेखा-चित्र: इंजन खोलो

नीचे C और Python की तुलना, compile का रास्ता, और भाषाओं की सीढ़ी — Python से 0-1 तक —

दाएँ की सीढ़ी पाठ-3 और आज के बीच का पुल है — सबसे ऊपर हरी Python, जो आपने लिखी; सबसे नीचे सुनहरी 0-1, जो मशीन असल में समझती है; बीच में C, जो दोनों दुनियाओं के सबसे पास खड़ी है।

ग़लतफ़हमी तोड़ो

ग़लतफ़हमी: "C इतनी पुरानी है — पचास साल से ज़्यादा! अब तो वह मर चुकी होगी, कोई नहीं सीखता। नई भाषाएँ आ गई हैं, पुरानी का क्या काम?"

सच: पुराना होना और बेकार होना अलग बातें हैं। गाँव का कुआँ या पत्थर का पुल पुराना है — पर आज भी पानी देता है, आज भी लोग उस पर चलते हैं; उसे गिराकर नया बनाना महँगा और ख़तरनाक, जब तक वह ठीक काम करे। C के साथ भी यही है: दुनिया की बहुत-सी बुनियादी चीज़ें — फ़ोन-कंप्यूटर के भीतरी तंत्र, दूसरी भाषाओं के अपने "इंजन" (हाँ, Python का सबसे आम रूप भी भीतर से C में लिखा है!), छोटी मशीनों के दिमाग़ — C पर टिकी हैं, और रोज़ नए काम भी उसमें होते हैं, ख़ासकर वहाँ जहाँ मशीन छोटी हो, बिजली कम हो, और रफ़्तार बहुत ज़रूरी। इसीलिए लोकप्रियता-सूचियों में वह आज भी ऊपर के स्थानों में मिलती है (पाठ-205)।

हाँ, यह सच है कि नई भाषाएँ आई हैं जो C जैसा काम ज़्यादा सुरक्षित ढंग से करने की कोशिश करती हैं (C में कुछ ग़लतियाँ — जैसे सूची की सीमा के बाहर हाथ डालना, पाठ-183 का मरीज़ — चुपचाप हो सकती हैं, जहाँ Python चिट्ठी दे देता है!)। पर भाषाएँ एक-दूसरे को "मारती" नहीं — वे साथ-साथ चलती हैं, हर एक अपने काम में (पाठ-205: औज़ार, प्रतियोगी नहीं)। और C सीखने का एक छिपा फ़ायदा भी है: वह सिखाती है कि मशीन असल में कैसे काम करती है — क़िस्में, याद, अनुवाद — जो किसी भी भाषा में आपको बेहतर कारीगर बनाता है। C पुरानी है, मरी नहीं — वह कुआँ है जिस पर आधा गाँव आज भी टिका है।

अभ्यास-खेल: इंजन-मश्क़

खेल 1 — C-नमूने का अनुवाद (काग़ज़ पर): ऊपर के C-नमूने को अपने शब्दों में पंक्ति-दर-पंक्ति कॉपी में लिखिए ("छपाई की पेटी लाओ · मुख्य पुर्ज़ा शुरू · ank नाम का पूरी-गिनती वाला डिब्बा, 40 ...")। फिर उलटा: अपने पाठ-188 के paas_hai पुर्ज़े को C जैसा लिखने की कोशिश कीजिए — int, धनु-कोष्ठक, अर्धविराम, printf (मशीन पर चलाना ज़रूरी नहीं — बोली पहचानना अभ्यास है)।

खेल 2 — क़िस्म पहले (सोच-प्रयोग): Python में (robot-मुक्त, अपनी फ़ाइल में) — x = 40 · x = "chaalis" · print(x) — चलता है? (हाँ — Python डिब्बे की क़िस्म बदलने देता है!) C में यही करने की कोशिश — int x = 40; फिर x में शब्द — अनुवादक रोकेगा। कॉपी में: "क़िस्म पहले बताने का फ़ायदा क्या, नुक़सान क्या?" (फ़ायदा: ग़लती जल्दी पकड़ी; नुक़सान: लिखने में ज़्यादा मेहनत।)

खेल 3 — सीढ़ी और घर की मशीनें + हुक्म-बही: घर में पाँच मशीनें खोजिए जिनमें छोटा "दिमाग़" है (रिमोट, वॉशिंग-मशीन, फ़ोन, डिजिटल घड़ी, स्मार्ट बल्ब...) — हर एक के आगे सोचिए: उसका code सीढ़ी के किस पायदान के पास होगा? पाठ-205 की तालिका की C-पंक्ति भरिए (क्रम · दोहराव · फ़ैसला if () { } · पुर्ज़ा int नाम() { } · छपाई printf)। हुक्म-बही के भाग-द पन्ने पर: "C = मशीन के पास · क़िस्म पहले (int) · { } और ; · printf · compile = पूरा अनुवाद पहले, फिर तेज़ · सीढ़ी: Python → C → असेंबली → 0-1 · पुरानी है, मरी नहीं"।

आगे क्या सीखेंगे

इंजन खुल गया — C कहाँ काम आती है (भीतरी तंत्र, छोटी मशीनें, IoT, ड्रोन), C-नमूने की बनावट (#include, main, int, धनु-कोष्ठक, अर्धविराम, printf), क़िस्म पहले बताने का नियम, compile बनाम दुभाषिया, और Python से 0-1 मशीन-भाषा तक की सीढ़ी — पाठ-3 का बीज, आज पूरा पेड़।

अगले पाठ में परिवार की वे सदस्य जो आपके हाथ के फ़ोन के ऐप बनाती हैं — Kotlin (कोटलिन) और Java (जावा)। आज Android फ़ोनों के लिए नए ऐप बनाने की मुख्य और सुझाई गई भाषा Kotlin है, और उसकी बड़ी बहन Java बैंकों और बड़ी कंपनियों के सिस्टमों में बरसों से चल रही है। उनकी बोली की झलक, Android ऐप सीखने का आधिकारिक मुफ़्त रास्ता, और एक ईमानदार सवाल — ऐप बनाने के लिए फ़ोन काफ़ी है या कंप्यूटर चाहिए? पाठ-212: कोटलिन (Kotlin)/जावा (Java) — ऐप बनाने वाले।
